# Contract v0.5 DRAFT R2: warning events, command changes and the event digest

Status: **amended draft R2 (2026-11-20) after Mayank's review; for review by Mayank (VCU), Pratham (HMI) and Saatwik
(decisions in section 9). Not implemented in the ERP.** Builds on v0.4 (`receipt-signing.md`); v0.3 and v0.4 uploads stay
accepted unchanged. Examples and digest vectors: `vectors/v05-event-vectors.json` (generated by
`tools/generate-v05-vectors.js`, digests re-checked independently by `tools/check_v05_vectors.py`).

Why: Saatwik decided that a protective warning seen **between** readings must count, and that warning detail codes
(AC310 `0x2031:11`, approved bounded SDO polling) decide outcomes per code. Mayank asked for durable command-change
events with step identity, explicit completeness, and a VCU-verifiable binding of the event evidence.

## 1. Opt-in and top-level fields

`contract_version: "0.5"` = the v0.4 body plus:

| Field | Type | Meaning |
|---|---|---|
| `capture_end_ms` | uint32 or null | run-relative time capture closed; null only for CANCEL (`started=false`) |
| `event_log` | object | completeness of the event journal (section 5) |
| `warnings` | array | warning journal records (section 2) |
| `command_changes` | array | effective command changes (section 3) |
| `event_digest` | `sha256:` + 64 hex | VCU-computed digest of both arrays (section 6) |

## 2. Time base

All event times are **run-relative milliseconds on the same origin as `samples[].t_ms`**: 0 = the VCU acquisition-clock
origin of the run, in `vcu.origin_boot_id`, at `start_uptime_ms`. Event `t_ms` is a **signed int32**:

- `t_ms < 0` — observed before capture started (only `phase: "PRE_START"`), e.g. a warning already active.
- `0 ≤ t_ms ≤ capture_end_ms` — `phase: "CAPTURE"`.
- `t_ms > capture_end_ms` — `phase: "POST_CAPTURE"`, e.g. a detail reply received after capture closed.

`phase` is sent explicitly and must agree with `t_ms` (rule `EVENT_PHASE`). Times are never clamped or invented; an event
whose time cannot be expressed on this origin is not exported and makes `event_log.complete = false`.
Equal `t_ms` values are allowed; **order is `seq` (warnings) and `step` (commands)**, never the timestamp.

## 3. `warnings[]`

| Field | Type | Meaning |
|---|---|---|
| `seq` | uint32 | journal order, 0, 1, 2, … without gaps |
| `t_ms` | int32 | event time (section 2); receive time for a detail record |
| `phase` | `PRE_START` \| `CAPTURE` \| `POST_CAPTURE` | must match `t_ms` |
| `kind` | see below | |
| `source` | `STATUS_BIT6` \| `VCU_LIMIT` \| `SDO_2031_11` | |
| `limit_id` | `[A-Z0-9_]{1,40}` or null | only with `VCU_LIMIT` |
| `code` | 0–65535 or null | only on `DETAIL` and `DETAIL_AMBIGUOUS` (raw value; unknown codes stay numbers) |
| `status_t_ms` | int32 or null | on detail kinds: time of the status observation that triggered the read |
| `reason` | `TIMEOUT` \| `ABORT` \| `MALFORMED` \| `LATE_REPLY` or null | only on `DETAIL_UNAVAILABLE` / `DETAIL_AMBIGUOUS` |
| `detail` | string ≤ 200 or null | free diagnostic text (e.g. SDO abort code); **not** part of the digest |

Kinds:

| kind | Sources | Meaning |
|---|---|---|
| `ACTIVE_AT_START` | STATUS_BIT6, VCU_LIMIT | warning already active when capture started (`t_ms ≤ 0`); opens an interval; **not** an observed transition |
| `RAISED` / `CLEARED` | STATUS_BIT6, VCU_LIMIT | observed transitions |
| `STATUS_UNKNOWN` / `STATUS_KNOWN` | STATUS_BIT6, VCU_LIMIT | warning status unavailable/stale from / again known from; opens/closes an unknown interval; **neither** is a transition |
| `DETAIL` | SDO_2031_11 | detail code read and attributed |
| `DETAIL_UNAVAILABLE` | SDO_2031_11 | no usable detail (`reason` TIMEOUT / ABORT / MALFORMED) |
| `DETAIL_AMBIGUOUS` | SDO_2031_11 | a value arrived but cannot be attributed (`reason` LATE_REPLY after the timeout); `code` = the raw value, never trusted |

Rules (422 `INCONSISTENT_RUN` unless 400 is stated):
- `EVENT_FIELDS` (400): field/kind/source combinations exactly as in the tables.
- `EVENT_ORDER`: `seq` 0…n−1; `t_ms` may repeat or be equal, order is `seq`.
- `EVENT_PHASE`: `phase` matches `t_ms` and `capture_end_ms`; `ACTIVE_AT_START` only with `t_ms ≤ 0`.
- `WARNING_PAIRING` per `source` + `limit_id`: states are *clear*, *active*, *unknown*. `RAISED` and `ACTIVE_AT_START` only
  from *clear* (or at the start); `CLEARED` only from *active*; `STATUS_UNKNOWN` from any state, `STATUS_KNOWN` only from
  *unknown* (after it the state is what the next transition says; the evaluator treats the unknown span as warning-active).
  A state still *active* or *unknown* at the end is allowed and counts.
- A clear before detail arrives never turns into "no warning": the `RAISED` interval stays as recorded; missing detail
  is a `DETAIL_UNAVAILABLE` record.
- `B6_COVERAGE` (**flag, not rejection**; Mayank's recommendation): a reading with b6 set that lies in no *active* or
  *unknown* interval of `STATUS_BIT6` / `VCU_LIMIT` is reported as an evidence-quality failure in the receipt and the
  run detail; the run is stored with all its evidence.

## 4. `command_changes[]`

| Field | Type | Meaning |
|---|---|---|
| `step` | uint32 | 0 = the first effective command applied by START, **always recorded, even if the RPM equals the pre-start baseline**; then 1, 2, … |
| `t_ms` | int32 ≥ 0 | VCU time the change took effect |
| `rpm_cmd` | int32 | the new effective command |
| `link` | see below | how the change relates to readings |
| `first_sample_seq` | uint32 or null | per `link` |

| link | first_sample_seq | Meaning |
|---|---|---|
| `OWNS_READING` | the reading carrying its b5 marker (stored, b5 set) | normal |
| `SUPERSEDED` | null | another change took effect before any reading was acquired; **only the latest change owns that reading's b5** |
| `NO_READING` | null | capture ended before a reading after this change was acquired |
| `READING_NOT_RETAINED` | the acquired reading's `sample_seq` (≥ `held_count`, not stored) | acquired but lost |

Rules: `COMMAND_ORDER` (`step` 0…n−1, `t_ms` non-decreasing; equal `t_ms` allowed, order is `step`);
`COMMAND_LINK` (an `OWNS_READING` seq is a stored reading with b5 set and `t_ms` ≥ the change; each stored b5 reading is
owned by exactly one change; a `READING_NOT_RETAINED` seq is ≥ `held_count`). Evaluation: a `SUPERSEDED`, `NO_READING` or
`READING_NOT_RETAINED` step has **no fresh readings** for `step_coverage` (decision S2).

## 5. `event_log` — completeness, separate from `recording_complete`

```json
"event_log": { "warnings_count": 7, "command_changes_count": 3, "complete": true, "lost_count": 0 }
```

`warnings_count` / `command_changes_count` must equal the array lengths (`EVENT_COUNTS`). `complete` = the VCU journal holds
every event of the run's capture window with no known loss; `lost_count` = number of known lost events (0 when complete,
integer ≥ 1 or null = unknown when not complete). Empty arrays with `complete: true` mean "no events occurred"; empty arrays
with `complete: false` prove nothing. `recording_complete` (readings) is unchanged and independent.

## 6. `event_digest` — VCU-verifiable binding

SHA-256 over little-endian binary records the VCU builds from its journal (free text `detail` excluded):

```
"MTEVT1\0\0"                              8 bytes
u32 warnings_count
per warning: u32 seq | i32 t_ms | u8 phase | u8 kind | u8 source | u8 reason | u8 present_mask |
             u16 code | i32 status_t_ms | u8 limit_id_len | limit_id ASCII          (absent values encoded as 0, mask says which are present:
                                                                                      b0 code, b1 status_t_ms, b2 limit_id)
u32 command_changes_count
per change:  u32 step | i32 t_ms | i32 rpm_cmd | u8 link | u8 has_first_sample_seq | u32 first_sample_seq
u8 event_log_complete | u32 lost_count (0xFFFFFFFF = unknown)
```

Enum codes: phase PRE_START 1, CAPTURE 2, POST_CAPTURE 3 · kind ACTIVE_AT_START 1, RAISED 2, CLEARED 3, STATUS_UNKNOWN 4,
STATUS_KNOWN 5, DETAIL 6, DETAIL_UNAVAILABLE 7, DETAIL_AMBIGUOUS 8 · source STATUS_BIT6 1, VCU_LIMIT 2, SDO_2031_11 3 ·
reason none 0, TIMEOUT 1, ABORT 2, MALFORMED 3, LATE_REPLY 4 · link OWNS_READING 1, SUPERSEDED 2, NO_READING 3,
READING_NOT_RETAINED 4. Digest string `sha256:` + 64 lowercase hex.

The ERP recomputes the digest from the uploaded arrays and stores `event_digest_match`. A v0.5 receipt uses signed message
**`MTRCPT2`** = the v1 message with these fields appended before the identifiers: `event_digest` (32, as uploaded),
`events_stored_digest` (32, ERP-computed), u32 `warnings_count`, u32 `command_changes_count`, u8 event flags
(b0 event digest match, b1 event log complete, b2 b6 coverage OK). The VCU releases event evidence only when the event
digests match its journal and the event log is complete. `MTRCPT1` stays for v0.4 runs. (Full byte layout and receipt
vectors follow once this draft is agreed.)

## 7. Accepted / rejected examples

`vectors/v05-event-vectors.json`: each case has the v0.5 additions, the expected ERP answer (accept, or the rule that
rejects or flags it) and, for accepted cases, the event digest. Highlights:

| Case | Expected |
|---|---|
| E1 warning raised and cleared during capture, detail read | accepted |
| E2 warning active at start, cleared later | accepted |
| E3 status unknown then known again, no transition | accepted (unknown span counts as active) |
| E4 detail reply after capture closed (POST_CAPTURE) | accepted |
| E5 late reply after timeout → DETAIL_AMBIGUOUS LATE_REPLY | accepted |
| E6 two changes before one reading (step 1 SUPERSEDED, step 2 owns it) | accepted |
| E7 reading acquired but not retained | accepted |
| E8 CANCEL: no events, complete log | accepted |
| R1 CLEARED without an open warning | 422 WARNING_PAIRING |
| R2 phase CAPTURE with negative t_ms | 422 EVENT_PHASE |
| R3 code on a RAISED record | 400 EVENT_FIELDS |
| R4 counts differ from array lengths | 422 EVENT_COUNTS |
| R5 two changes claim the same b5 reading | 422 COMMAND_LINK |
| R6 seq gap in warnings | 422 EVENT_ORDER |
| R7 event_digest does not match the arrays | stored, receipt `event_digest_match = false` (no release) |
| F1 b6 reading outside any warning interval | stored, flagged B6_COVERAGE |

## 8. Capacity

The ERP accepts up to 10,000 warnings and 10,000 command changes per upload. The VCU's current host-test bounds (32 queued,
256 journal records) are separate; nothing is ever silently truncated — a loss is `event_log.complete = false`.

## 9. Decisions needed from Saatwik (testing head)

- **S1** status unknown/stale during capture counts as a warning for "any b6" → INVALID (it is already b6 by definition).
- **S2** a step whose change is `SUPERSEDED`, `NO_READING` or `READING_NOT_RETAINED` fails `step_coverage` → INVALID.
- **S3** missing (`DETAIL_UNAVAILABLE`), ambiguous (`DETAIL_AMBIGUOUS`) or unknown detail codes → INVALID.
- **S4** `event_log.complete = false` → INVALID (absence of warnings cannot be shown).
- **S5** `B6_COVERAGE` failure → INVALID (evidence quality).
- **S6** the per-code FAIL / INVALID / N/A / log table is part of the versioned criteria (published and locked with them).
