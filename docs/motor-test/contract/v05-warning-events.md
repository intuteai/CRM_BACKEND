## 1. Opt-in and top-level fields

`contract_version: "0.5"` = the v0.4 body plus:

| Field | Type | Meaning |
|---|---|---|
| `capture_end_ms` | uint32 or null | run-relative time capture closed; **null exactly for CANCEL** (`started=false`) |
| `event_log` | object | completeness of the event journal (section 5) |
| `warnings` | array | warning journal records (section 3) |
| `command_changes` | array | effective command changes (section 4) |
| `event_digest` | `sha256:` + 64 hex | VCU-computed digest MTEVT2 (section 6) |

**Shapes (rule `CANCEL_SHAPE`, 422):** a started run has `capture_end_ms` and `start_uptime_ms`; a CANCEL has
`capture_end_ms: null`, no warnings and no command changes (no command was applied). Preflight warnings for a CANCEL
would need their own clock origin; they are not part of v0.5.

## 2. Time base

All event times are **run-relative milliseconds on the same origin as `samples[].t_ms`**: 0 = the VCU acquisition-clock
origin of the run, in `vcu.origin_boot_id`, at `start_uptime_ms` (`start_uptime_ms` is bound into the MTEVT2 digest; `origin_boot_id` is not in MTEVT2 but is signed in MTRCPT2 and compared with the VCU manifest). Event `t_ms` is a
**signed int32**: `< 0` only `PRE_START`; `0 … capture_end_ms` `CAPTURE`; `> capture_end_ms` `POST_CAPTURE`
(rule `EVENT_PHASE`). Times are never clamped or invented; evidence that cannot be expressed on this origin (e.g. a
different clock epoch) is retained by the VCU and the log is exported with `event_log.complete = false`.
**Order is `seq` / `step`, never the timestamp; equal `t_ms` values are allowed, decreasing ones are not**
(`EVENT_ORDER`, `COMMAND_ORDER`).

## 3. `warnings[]`

| Field | Type | Meaning |
|---|---|---|
| `seq` | uint32 | journal order; 0…n−1 when the log is complete, strictly increasing with gaps (lost events) when not |
| `t_ms` | int32 | event time; receive time for detail records; non-decreasing in `seq` order |
| `phase` | `PRE_START` \| `CAPTURE` \| `POST_CAPTURE` | must match `t_ms` |
| `kind` | see below | |
| `source` | `STATUS_BIT6` \| `VCU_LIMIT` \| `SDO_2031_11` | |
| `limit_id` | `[A-Z0-9_]{1,40}` or null | only and always with `VCU_LIMIT` |
| `code` | 0–65535 or null | only on `DETAIL` and `DETAIL_AMBIGUOUS` (raw value; unknown codes stay numbers) |
| `status_t_ms` | int32 or null | detail kinds only: time of the triggering status observation; **must be ≤ `t_ms`** (`EVENT_CAUSALITY`) |
| `reason` | `TIMEOUT` \| `ABORT` \| `MALFORMED` \| `LATE_REPLY` or null | `DETAIL_UNAVAILABLE` (not LATE_REPLY) / `DETAIL_AMBIGUOUS` (only LATE_REPLY) |
| `restored_state` | `ACTIVE` \| `CLEAR` or null | **only and always on `STATUS_KNOWN`**: the warning state actually observed when status became known again |
| `detail` | string ≤ 200 or null | free diagnostic text; **not** part of the digest |

All enum values are matched as exact own values (`toString`, `constructor` etc. are rejected, 400 `EVENT_FIELDS`).

| kind | Sources | Meaning |
|---|---|---|
| `ACTIVE_AT_START` | STATUS_BIT6, VCU_LIMIT | warning already active when capture started (`t_ms ≤ 0`); opens an interval; not a transition |
| `RAISED` / `CLEARED` | STATUS_BIT6, VCU_LIMIT | observed transitions |
| `STATUS_UNKNOWN` | STATUS_BIT6, VCU_LIMIT | status unavailable/stale from here; not a transition |
| `STATUS_KNOWN` | STATUS_BIT6, VCU_LIMIT | status known again, with `restored_state`; not a transition |
| `DETAIL` / `DETAIL_UNAVAILABLE` / `DETAIL_AMBIGUOUS` | SDO_2031_11 | detail read attributed / no usable detail / late value, never trusted |

`WARNING_PAIRING` per `source` + `limit_id`, states *clear*, *active*, *unknown*: `ACTIVE_AT_START` and `RAISED` only from
*clear*; `CLEARED` only from *active*; `STATUS_UNKNOWN` from any state; `STATUS_KNOWN` only from *unknown*, and the new
state is its `restored_state` (so a warning still active after recovery can later produce a genuine `CLEARED`, vector
E9). The unknown span counts as warning-active for evaluation (S1). A clear before detail arrives never turns into "no
warning"; missing detail is a `DETAIL_UNAVAILABLE` record. `B6_COVERAGE` (flag, not rejection): a reading with b6 set
outside every *active* / *unknown* interval is reported as an evidence-quality failure; a `STATUS_KNOWN` with
`restored_state: ACTIVE` keeps the interval open (vector F2).

## 4. `command_changes[]`

| Field | Type | Meaning |
|---|---|---|
| `step` | uint32 | 0 = the first effective command applied by START, always recorded (even if the RPM equals the pre-start baseline); 0…n−1 when the log is complete; strictly increasing with gaps, **never renumbered**, when it is not |
| `t_ms` | int32, 0 ≤ t ≤ `capture_end_ms` | VCU time the change took effect (`COMMAND_WINDOW`: no change after capture closed) |
| `rpm_cmd` | int32 | the new effective command |
| `link` | see below | |
| `first_sample_seq` | uint32 or null | per `link` |

| link | first_sample_seq | Rule (`COMMAND_LINK`) |
|---|---|---|
| `OWNS_READING` | the reading carrying its b5 marker | stored, b5 set, `t_ms` ≥ the change, its `rpm_cmd` equals the change's; each reading owned once |
| `SUPERSEDED` | null | a later change exists in the array (only the latest change before a reading owns its b5) |
| `NO_READING` | null | only the last change (capture ended before a reading) |
| `READING_NOT_RETAINED` | the acquired reading's `sample_seq` | ≥ `held_count` (acquired but lost) |

Linked readings (`OWNS_READING`, `READING_NOT_RETAINED`) must increase with the step (acquisition order; vector P09).
**Complete log:** a started run must contain step 0 (`COMMAND_MISSING_STEP0`, vector P01) and every stored b5 reading
must be owned. **Incomplete log:** lost changes leave gaps in `step`; remaining changes keep their real identities
(vector E10); orphan b5 readings are allowed (their owner may be lost). Evaluation: a `SUPERSEDED`, `NO_READING` or
`READING_NOT_RETAINED` step has no fresh readings for `step_coverage` (S2).

## 5. `event_log` — completeness, separate from `recording_complete`

`{ "warnings_count": n, "command_changes_count": m, "complete": true|false, "lost_count": … }` — counts equal the array
lengths (`EVENT_COUNTS`). `lost_count` = 0 when complete; when not complete, `null` (unknown) or **1 … 4294967294**
(4294967295 is never valid, vector C1). Empty arrays with `complete: true` mean "no events"; with `complete: false`
they prove nothing.

**Incomplete logs (R4).** Strict pairing and successor proofs apply to complete logs. With `complete: false`, a record
whose partner may have been lost (a `CLEARED` or `STATUS_KNOWN` whose opening event is missing; a `SUPERSEDED` whose
successor is missing) is **kept as recorded** and returned in `unproven[]` with the rule it could not prove. This is only
allowed when a loss can explain it: a seq gap at or before the record (or a first seq above 0), or an unknown loss count;
otherwise it is impossible evidence and stays rejected (vector G3). Unproven relationships are evidence-quality facts for
evaluation (S4 makes the run INVALID anyway), never silent repairs; intervals are not invented and unknown warning
presence is never treated as clear.

## 6. `event_digest` — MTEVT2 (VCU-verifiable)

SHA-256 over little-endian bytes the VCU builds from its journal and manifest (free text `detail` excluded). An optional
value is always encoded as **u8 presence (0/1) + the value (0 when absent)** — no sentinels.

```
"MTEVT2\0\0"                                           8 bytes
u8 started | opt u32 capture_end_ms | opt u32 start_uptime_ms
u32 warnings_count
per warning: u32 seq | i32 t_ms | u8 phase | u8 kind | u8 source | u8 reason | u8 restored_state |
             u8 present_mask (b0 code, b1 status_t_ms, b2 limit_id) | u16 code | i32 status_t_ms |
             u8 limit_id_len | limit_id ASCII
u32 command_changes_count
per change:  u32 step | i32 t_ms | i32 rpm_cmd | u8 link | u8 has_first_sample_seq | u32 first_sample_seq
u8 event_log_complete | opt u32 lost_count
```

Enum codes: phase PRE_START 1, CAPTURE 2, POST_CAPTURE 3 · kind ACTIVE_AT_START 1, RAISED 2, CLEARED 3,
STATUS_UNKNOWN 4, STATUS_KNOWN 5, DETAIL 6, DETAIL_UNAVAILABLE 7, DETAIL_AMBIGUOUS 8 · source STATUS_BIT6 1, VCU_LIMIT 2,
SDO_2031_11 3 · reason none 0, TIMEOUT 1, ABORT 2, MALFORMED 3, LATE_REPLY 4 · restored_state none 0, ACTIVE 1, CLEAR 2 ·
link OWNS_READING 1, SUPERSEDED 2, NO_READING 3, READING_NOT_RETAINED 4.

Changing `capture_end_ms` (or the start origin) changes the digest (vector D1). The ERP recomputes the digest from the
uploaded arrays plus the run's `started`, `capture_end_ms` and `start_uptime_ms`, stores `event_digest_match`, and signs
both digests, the counts, the event flags and the capture bounds in **MTRCPT2** (`receipt-signing.md`), so the VCU
compares them field by field with its own manifest.

## 7. Settle boundary (with `criteria-flag-rules.md`)

One boundary for both rules: a reading at exactly `t_b5 + X` is **inside** the settle window. `flag_exclusion` ignores
`[t_b5, t_b5 + X]`; `step_coverage` counts only readings with `t_ms > t_b5 + X`. Example X = 1500, b5 at 1000 ms:
2499 ms → excluded, 2500 ms → excluded, 2501 ms → counted. (Five fresh readings per step is the testing head's rule,
not yet a measured bench result.)

## 9. Capacity

The ERP accepts up to 10,000 warnings and 10,000 command changes per upload. The VCU's host-test bounds (32 queued, 256
journal records) are separate; nothing is ever silently truncated — a loss is `event_log.complete = false`.

## 10. Testing-head decisions (Saatwik, 2026-11-21)

- **S1** status unknown/stale during capture counts as a warning for "any b6" → **INVALID** (decided).
- **S2** a step whose change is `SUPERSEDED`, `NO_READING` or `READING_NOT_RETAINED` fails `step_coverage` → **INVALID** (decided).
- **S3** missing (`DETAIL_UNAVAILABLE`), ambiguous (`DETAIL_AMBIGUOUS`) or unknown detail codes → **INVALID** (decided).
- **S4** `event_log.complete = false` → **INVALID** (decided; includes runs with unproven relationships).
- **S5** `B6_COVERAGE` failure → **INVALID** (decided).
- **S6** the per-code FAIL / INVALID / N/A / log table is **versioned with the criteria** (decided).
- Still to confirm: the settle boundary in section 7 (reading at exactly `t_b5 + X` still settling; Mayank and Pratham
  agree), the numeric profile and the code table itself (limits sheet, T046).

INVALID evidence is always stored and reported, never hidden; it only means the run cannot be PASS/FAIL. Verification of
a receipt is never permission to delete data (separate retention/release agreement).

## 11. Open

Unfinalized evidence (unknown counts, uncertain resets) keeps its separate ingestion path (not in v0.5); the
retention/release agreement before ACK_ARCHIVED is separate; device verification and bench measurements are Mayank's.
